# Integer programming: valid cuts and complete search

A fractional production plan can consume exactly the available capacity while asking a factory to ship half a machine. Divisibility is then the wrong model. Requiring selected quantities to be integers changes the feasible set and invalidates the argument that a continuous LP optimum is an executable plan.

Consider an original teaching example with two whole products. Maximize $5x_1+4x_2$ subject to $6x_1+4x_2\le24$, $x_1+2x_2\le6$, and $x_1,x_2\in\mathbb Z_{\ge0}$. The symbol $\mathbb Z_{\ge0}$ denotes nonnegative integers. The continuous optimum is $(3,3/2)$ with value 21. The best integer plan is $(4,0)$ with value 20. The difference is small here, but its cause is structural: the integer feasible set excludes the continuous optimum.

## 1. Relaxation supplies a bound, not a shipment [00:16](https://www.youtube.com/watch?v=gxLQ7Q26SkE&t=16s)

An **integer linear program** has a linear objective, linear constraints, and integer restrictions on selected variables. A **pure integer** problem restricts every decision variable; a **mixed-integer linear program** restricts only a subset while leaving other variables continuous. A **binary** variable is integer with bounds zero and one. It can encode a yes-or-no decision such as opening a facility.

Dropping integrality gives the **LP relaxation**. Every integer feasible point remains feasible in the relaxation, so for maximization its optimum $U$ is an upper bound on the integer optimum $Z^*$. Any known integer feasible plan with value $L$ supplies a lower bound. The inequalities $L\le Z^*\le U$ distinguish the roles of the relaxation and the feasible incumbent.

For the example, the binding LP equations give $x_1=3,x_2=3/2$. A dual certificate is $y=(3/4,1/2)$: the product valuations are $6(3/4)+1/2=5$ and $4(3/4)+2(1/2)=4$, and the capacity valuation is $24(3/4)+6(1/2)=21$. Thus 21 is an upper bound even before an integer search starts.

Rounding is a heuristic that needs a new feasibility check. Rounding $(3,3/2)$ upward gives $(3,2)$, which uses 26 units of the first resource and seven of the second, violating both limits. Rounding downward gives $(3,1)$, which is feasible but earns 19, below the true optimum 20. Even downward rounding is not universally feasible: a covering row $x_1+x_2\ge3/2$ can be satisfied at $(3/4,3/4)$ and violated after flooring both entries.

Integer data do not guarantee integer vertices. The one-dimensional constraint $2x\le3$ has integer coefficients but continuous maximizer $x=3/2$. Certain network matrices have a stronger integrality property, developed in Chapter 5. General integer programming cannot borrow that result merely because the coefficients happen to be whole numbers.

The size of the **integrality gap** depends on its convention. Here the additive gap is $21-20=1$, and the ratio of the LP bound to the positive integer optimum is $21/20$. A ratio is unsuitable when the denominator vanishes or objectives can change sign. Report the definition and bounds explicitly, especially when a solver stops before closing the gap.

## 2. A valid cut removes fractions while preserving integers [04:24](https://www.youtube.com/watch?v=gxLQ7Q26SkE&t=264s)

A **valid inequality** holds for every integer feasible point. A **cut** is a valid inequality violated by the current fractional relaxation solution. The two conditions are separate. An inequality that removes the current point but also removes the true integer optimum is not a valid cutting plane.

Add the first resource row to twice the second:

$$8x_1+8x_2\le36,\qquad x_1+x_2\le9/2.$$

Since $x_1+x_2$ is integer, this implies $x_1+x_2\le4$. The fractional point $(3,3/2)$ violates the strengthened inequality, while every integer feasible point satisfies it. This is a simple aggregation-and-rounding cut. Flooring the right-hand side is justified only because the entire left side is integer after the division; indiscriminately flooring a right side with fractional coefficients would be invalid.

The cut also certifies the integer optimum. Nonnegative $x_2$ gives

$$5x_1+4x_2=5(x_1+x_2)-x_2\le20.$$

The plan $(4,0)$ attains 20 and satisfies both original resources. This proves optimality without enumerating every integer combination. The inequality has supplied the missing information that the original LP relaxation did not encode.

Geometrically, let $S$ be the integer feasible set and let $\operatorname{conv}(S)$ be its convex hull. A linear objective has the same supremum over $S$ and its convex hull. If that hull had a tractable exact inequality description, integer optimization could be solved as an LP over the hull. Cutting planes approximate this description by adding valid restrictions. The difficult part is finding useful inequalities and managing their number, not merely changing the solver's numerical tolerance.

## 3. Derive the pure Gomory fractional cut [09:12](https://www.youtube.com/watch?v=gxLQ7Q26SkE&t=552s)

Suppose a simplex row for a pure integer problem has the form

$$x_B+\sum_{j\in N}a_jx_j=b,$$

where the basic variable $x_B$ and every nonbasic variable in the sum must be nonnegative integers. The basis coefficients $a_j$ and right side $b$ can be fractional even when the original data are integers. Let $f(t)=t-\lfloor t\rfloor\in[0,1)$ denote the fractional part, including for negative $t$. In particular $f(-1/8)=7/8$, not $-1/8$.

Subtract the integer part of each coefficient from the row. The expression

$$b-\sum_j f(a_j)x_j
=x_B+\sum_j\lfloor a_j\rfloor x_j$$

is integer. Since $x_j\ge0$ and $f(a_j)\ge0$, it is at most $b$. An integer at most $b$ is at most $\lfloor b\rfloor$. Rearranging yields

$$\sum_j f(a_j)x_j\ge f(b).$$

At the current basic solution every $x_j$ in the sum is zero. If $b$ is fractional, the right side is positive and the point is excluded. For every integer feasible solution, the preceding integer argument proves validity. The [ETH discrete optimization notes, §8.2](https://people.inf.ethz.ch/gaertner/subdir/teaching/lecture_notes/do.pdf) develop this construction; the derivation here exposes the exact use of integrality and nonnegativity.

For the example add integer slacks $s_1=24-6x_1-4x_2$ and $s_2=6-x_1-2x_2$. The LP basis consisting of the product columns has the row

$$x_2-\frac18s_1+\frac34s_2=\frac32.$$

The fractional cut is $(7/8)s_1+(3/4)s_2\ge1/2$. Multiplying by eight gives $7s_1+6s_2\ge4$. Substituting back produces $6x_1+5x_2\le25$. The LP optimum gives $25.5$ and is removed; the integer plan $(4,0)$ gives 24 and survives. This cut is valid but weaker than the earlier aggregated cut for proving the final bound in one step.

Writing a violated cut as $-\sum_j f(a_j)x_j+s=-f(b)$ creates a negative slack at the old solution. Its new reduced cost is zero, so dual simplex can repair feasibility while retaining the old objective certificate structure. After reoptimization another fractional row may need a cut. If newly added slack variables are treated as integer in a later pure-integer derivation, the inequalities must be scaled and the integrality implication justified. A fractional-coefficient cut does not make its unscaled slack integer automatically.

Cut selection by largest fractional right side is a possible heuristic. It is not a theorem that the largest fraction yields the strongest cut or smallest search tree. Floating-point tableau rows near integers require special care: a tiny coefficient error can become a formally invalid cut if interpreted as exact rational data.

## 4. Mixed integrality requires a different argument [42:27](https://www.youtube.com/watch?v=hv73gBIeMpg&t=2547s)

The pure fractional proof fails when some $x_j$ are continuous, because $\lfloor a_j\rfloor x_j$ need not be integer. A simpler valid mixed-integer **split cut** uses only the integrality of $x_B$ in the row. Let $f=f(b)$ satisfy $0<f<1$, and define nonnegative quantities

$$u=\sum_{a_j>0}a_jx_j,\qquad
v=\sum_{a_j<0}(-a_j)x_j.$$

Then $x_B=b-u+v$. Every integer $x_B$ satisfies either $x_B\le\lfloor b\rfloor$ or $x_B\ge\lceil b\rceil$. In the first branch $u-v\ge f$, so $u+fv/(1-f)\ge f$. In the second branch $v-u\ge1-f$, giving the same inequality because $u\ge0$. Hence

$$u+\frac{f}{1-f}v\ge f$$

is valid for the union of the two integer branches and cuts off the current point $u=v=0$. This proof does not require the nonbasic variables to be integer. Further strengthening can exploit any of their integer restrictions; it must preserve the different assumptions.

Take a mixed problem maximizing $x_1+x_2$ with $3x_1+2x_2\le5$, $x_2\le2$, $x\ge0$, and only $x_1$ integer. The LP solution is $(1/3,2)$, value $7/3$. With slacks $s_1,s_2$, the basic row is $x_1+(1/3)s_1-(2/3)s_2=1/3$. Thus $f=1/3$, $u=s_1/3$, and $v=2s_2/3$. The split cut becomes $s_1+s_2\ge1$, or $x_1+x_2\le2$ after substitution and division by three.

Both $(0,2)$ and $(1,1)$ attain two and meet the mixed restrictions. The cut proves no mixed feasible point can do better. Requiring $x_2$ also to be integer is unnecessary for this conclusion; conversely, forcing a continuous variable to be integer in a solver would change the specified model even if an instance happened to retain its optimum.

## 5. Branch-and-bound must keep every unpruned branch [00:53](https://www.youtube.com/watch?v=hv73gBIeMpg&t=53s)

At a fractional LP optimizer choose an integer-restricted variable $x_j^*$. Every feasible integer point satisfies one of the disjoint alternatives $x_j\le\lfloor x_j^*\rfloor$ or $x_j\ge\lceil x_j^*\rceil$. These define two child nodes whose union contains every integer feasible point in the parent. The open interval between floor and ceiling contains no integers, so removing it is safe.

Each node keeps all its ancestors' restrictions. Branching on a second variable does not remove an earlier lower or upper bound. A variable that becomes integer in one relaxation is not permanently fixed unless an actual node restriction fixes it. Losing inherited restrictions can cause overlapping or missing subproblems and invalidate the final certificate.

Solve the node's LP relaxation to obtain an upper bound $U_N$. Maintain an **incumbent**, the best known integer feasible plan, with value $L$. A node can be **fathomed**, meaning removed from further consideration, when its relaxation is infeasible, its bound cannot exceed $L$, or its relaxation optimizer already satisfies all required integrality conditions. In the last case it supplies an integer optimum for that node and can update the incumbent.

An LP upper bound of 10.8 is not an integer feasible value of 10.8. A second node with bound 10.1 might contain an integer plan worth ten while the first contains no integer feasible point. The relative ordering of two bounds therefore does not justify deleting the smaller-bound node. Best-bound selection chooses which node to inspect next; it does not discard the remaining queue.

This distinction repairs an unsafe pruning suggestion in lecture 12 near [30:11](https://www.youtube.com/watch?v=hv73gBIeMpg&t=1811s). Comparing a node bound with an actual incumbent justifies deletion. Comparing it only with a sibling's fractional relaxation bound does not. The complete search invariant is that every feasible integer plan belongs either to a live node or to a node already proved unable to improve the incumbent.

For bounded integer variable domains, repeated branching eventually fixes the integer variables along each path, giving a finite tree under exact arithmetic and complete node processing. With unbounded domains, termination needs additional argument. A computational time limit also stops the algorithm without proving optimality unless the remaining bounds already close the gap.

## 6. A complete tree and an executable certificate [13:43](https://www.youtube.com/watch?v=hv73gBIeMpg&t=823s)

Return to the product example with LP optimizer $(3,3/2)$ and bound 21. Branch on $x_2$. The node $x_2\ge2$ has relaxation optimizer $(2,2)$ with value 18; it is integer, so 18 becomes an incumbent and this node is complete. The node $x_2\le1$ has optimizer $(10/3,1)$ with bound $62/3$, so it remains live.

Branch that node on $x_1$. Its child $x_1\ge4$ has optimizer $(4,0)$ and value 20, improving the incumbent. Its child $x_1\le3$ has bound 19 and can be pruned against 20. Every branch is now processed, and the incumbent is optimal. The tree visits five nodes including the root. The separate cut proof gave the same answer through a different certificate.

The [chapter lab](labs/ch04.py) implements this bounded small-example branch-and-bound using LP relaxations. It takes finite arrays and integer variable indices; its node stack stores bounds, its incumbent stores an integer feasible vector, and its output records every node decision. The implementation raises on unexpected LP statuses and on a node limit rather than presenting an incomplete run as optimal. Its tolerance is a numerical convenience, so the final point is rounded only after integrality checks and then rechecked against the original constraints.

The lab compares its answer against exhaustive enumeration of the finite feasible grid and SciPy's [mixed-integer solver](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.milp.html). It also checks the Gomory cut on every enumerated integer point and solves the mixed example with an integrality mask. Exhaustive enumeration certifies this tiny grid, while the general branch and cut arguments explain the method beyond that example.

An implementation should report the incumbent value, best remaining bound, termination reason, and feasibility residuals. Commercial-scale mixed-integer optimization also uses presolve, valid cuts, branching heuristics, and numerical safeguards. Those mechanisms change efficiency without replacing the logical requirement that every pruning action be justified by a valid bound.

## Six worked problems

### Exercise 1 — A failed rounding rule

Find a covering constraint and a fractional feasible point whose componentwise floor is infeasible.

<details><summary>Worked solution</summary>

Use $x_1+x_2\ge3/2$ and $x\ge0$. The point $(3/4,3/4)$ satisfies the row at equality, while flooring gives $(0,0)$ and violates it. Downward rounding can preserve nonnegative packing rows with at-most capacities, but covering and equality requirements require separate treatment.
</details>

### Exercise 2 — A negative fractional coefficient

Compute the fractional parts of $-7/4$, $5/3$, and $-2$, and explain why truncating toward zero is wrong for Gomory cuts.

<details><summary>Worked solution</summary>

The floors are $-2,1,-2$, so the fractional parts are $1/4,2/3,0$. Truncating $-7/4$ toward zero gives $-1$ and a remainder $-3/4$, which is negative. The validity derivation uses nonnegative fractional coefficients and nonnegative variables. A signed remainder would break the step bounding the integer expression by $b$.
</details>

### Exercise 3 — Prove the aggregated cut

Derive $x_1+x_2\le4$ for the product example and use it to prove its integer optimum.

<details><summary>Worked solution</summary>

Adding the first inequality to twice the second gives $8(x_1+x_2)\le36$. Since the sum is integer, it is at most four. Then $5x_1+4x_2=5(x_1+x_2)-x_2\le20$. The point $(4,0)$ uses 24 and four resource units, so it is feasible and reaches the upper bound. Feasible attainment and the valid inequality together establish optimum 20.
</details>

### Exercise 4 — Safe pruning

An incumbent earns 20. Three nodes have valid LP upper bounds 19.8, 20, and 20.4. Which can be pruned if only one optimizer is required?

<details><summary>Worked solution</summary>

The first two cannot improve on 20 and can be pruned. The third still might, so its bound alone does not justify deletion. If all objective values are known integers, then a bound of 20.4 can be tightened to 20 and also pruned. That extra inference requires integer-valued objectives on all feasible integer plans, which can fail in mixed-integer models with continuous contributions.
</details>

### Exercise 5 — A continuous variable in a pure cut proof

Which step of Section 3 fails if $x_j$ is continuous, and how does the split argument avoid it?

<details><summary>Worked solution</summary>

The expression $x_B+\sum_j\lfloor a_j\rfloor x_j$ need not be integer, so being at most $b$ no longer implies being at most $\lfloor b\rfloor$. The split proof instead uses the integer basic variable to divide feasible points into $x_B\le\lfloor b\rfloor$ or $x_B\ge\lceil b\rceil$. It derives one inequality valid in both branches using only nonnegativity of the remaining variables.
</details>

### Exercise 6 — A completed node is not a completed tree

One child has an integer optimizer worth 18, while its sibling's LP bound is 20.7. Can the algorithm stop?

<details><summary>Worked solution</summary>

No. The integer point establishes an incumbent and resolves its own node. The sibling may contain a plan worth more than 18 and must remain live. The algorithm stops with a proof only after every live node is infeasible, integer-complete, or bounded by the incumbent. Finding one feasible plan is a useful milestone but does not close the global gap.
</details>
