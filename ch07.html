A delivery planner needs the cheapest route from a depot to a customer. A second planner must visit every customer and return to the depot. Both use the same road-cost table. The second problem has an additional connectivity requirement that changes the mathematics and computational difficulty. Solving many individually cheap connections does not automatically produce one legal tour.

We use two original teaching constructions. The first is a directed network with arcs $s\to a$ of cost 4, $s\to b$ of cost 1, $b\to a$ of cost 2, $a\to t$ of cost 1, and $b\to t$ of cost 7. The second has four cities arranged into two cheap pairs: traveling within either pair costs 1, while traveling between pairs costs 9. Costs can be time or money, but one instance must use one consistent additive quantity.

1. A graph separates available moves from chosen moves 00:49

A directed graph $G=(V,E)$ consists of a finite vertex set $V$ and a set $E$ of ordered pairs called arcs. Arc $(u,v)$ permits travel from $u$ to $v$. Its reverse is a separate possible arc. An undirected edge instead permits both directions; the two directions have the same weight in the undirected weighted model. Real one-way streets or asymmetric tolls require a directed model.

A walk follows a sequence of adjacent vertices and may revisit vertices. A simple path does not revisit vertices. A trail does not revisit edges. These distinctions matter when negative-cost cycles or visit-once requirements appear. A path's unweighted length counts edges; its weighted cost is the sum of the specified edge weights. The number of road segments need not rank routes in the same order as travel time.

Let $w(u,v)$ be the cost of an available arc. A weighted adjacency representation must distinguish a zero-cost arc from an absent arc. A dense table can store $+\infty$ for absent arcs and zero on its diagonal for a zero-length walk. An adjacency list stores only available arcs. Confusing absence with zero makes nonexistent roads appear free.

Define the shortest-path distance $\delta(s,v)$ as the infimum of walk costs from the source $s$ to vertex $v$. It is $+\infty$ if $v$ is unreachable. With nonnegative weights, a repeated-vertex cycle can be removed without increasing cost, so a finite reachable optimum has a simple-path representative. With a reachable negative cycle that can also reach $v$, repeated traversal drives walk costs to $-\infty$. Demanding a simple path instead would change that negative-weight problem.

The single-source problem asks for distances from one fixed $s$ to every vertex. The single-pair problem asks only about $s$ and one destination $t$. The all-pairs problem asks for every ordered vertex pair. A shortest-path tree from $s$ contains useful optimal subpaths along its own branches, but does not by itself answer arbitrary all-pairs queries. Two customers on different branches may have their cheapest connecting path elsewhere in the graph.

2. Relaxation improves a discovered route 25:13

Maintain a tentative distance $d(v)$ and a predecessor $\pi(v)$. A finite tentative distance is the cost of a route already discovered, so it is an upper bound on the true optimum. Initialize $d(s)=0$, all other distances to $+\infty$, and all predecessors to empty. For an arc $(u,v)$, relaxation applies

$$d(v)\leftarrow\min\{d(v),d(u)+w(u,v)\}.$$

When the second term is strictly smaller, also set $\pi(v)=u$. This update appends one available arc to an existing route. It cannot create an artificially low cost unsupported by a route. It can improve the same vertex several times before its final label is known.

The running network illustrates why discovery is not finality. Relaxing the source gives $d(a)=4$ and $d(b)=1$. The direct route to $a$ has been discovered, but it is not shortest: after considering $b$, the route $s\to b\to a$ lowers $d(a)$ to 3. A method that permanently accepts every first discovered route would return the wrong answer on this nonnegative graph.

Shortest paths have optimal substructure: a subpath of an optimal path is optimal between its endpoints under the same additive cost model. Otherwise replacing it with a cheaper subpath produces a cheaper complete route. The argument uses concatenation and additive costs. If a cost depends on the entire visit history, the vertex alone may not describe the relevant state. Turn restrictions, remaining fuel, or time windows may require an expanded state space.

The lecture's predecessor array is one way to retain an actual route, not just its cost. If several shortest routes exist, one predecessor may select one of them. Uniqueness is not guaranteed by the problem definition. Recording every equal-cost predecessor can represent more possibilities, but zero-cost cycles then require care: the predecessor relation need not be a tree.

3. Dijkstra finalizes the smallest unsettled label 32:00

For finite nonnegative arc weights, Dijkstra's algorithm repeatedly selects an unsettled vertex with the smallest tentative label, marks it settled, and relaxes its outgoing arcs. A settled label is claimed to equal the true shortest distance. The distinction between a discovered route and a settled label is the algorithm's essential invariant.

Here is the proof. Assume previously settled labels are correct, and let $u$ be the smallest unsettled label. If an optimal route to $u$ passes through unsettled vertices, let $y$ be the first such vertex and $x$ its settled predecessor on that route. Relaxing $(x,y)$ has already made $d(y)$ no greater than the optimal prefix cost to $y$. Since tentative labels are discovered-route costs, it cannot be smaller than that optimum; the prefix label is therefore correct. Nonnegative remaining arc costs imply $\delta(s,y)\le\delta(s,u)$. By minimum selection,

$$d(u)\le d(y)=\delta(s,y)\le\delta(s,u)\le d(u).$$

Every inequality must be equality. Thus $d(u)=\delta(s,u)$, completing the induction. If every remaining tentative label is infinite, none of those vertices is reachable; the procedure can stop.

For our graph the settled order is $s,b,a,t$. After settling $s$, labels are $(d(a),d(b),d(t))=(4,1,\infty)$. Settling $b$ gives $(3,1,8)$. Settling $a$ reduces $d(t)$ to 4, after which settling $t$ completes the reachable portion. The route is reconstructed backward as $t,a,b,s$, then reversed to $s,b,a,t$. Its cost is $1+2+1=4$.

An unreachable vertex $z$ retains infinite distance and no predecessor. Treating that empty predecessor as a valid zero-length route would be a reporting error. Route reconstruction should explicitly distinguish source, reachable destination, and unreachable destination.

Nonnegativity is a proof condition, not a coding preference

Replace the example with arcs $s\to a$ of cost 2, $s\to b$ of cost 5, and $b\to a$ of cost $-4$. A label-setting implementation settles $a$ at 2 before visiting $b$, but the route through $b$ costs 1. There is no negative cycle. The failure is already caused by a negative edge: the inequality comparing a path prefix with its full cost no longer holds.

Bellman–Ford instead uses repeated relaxation to account for paths with increasing numbers of arcs, and can detect a reachable negative cycle. It is not correct to define its distinction from Dijkstra merely as “a vertex can be relaxed more than once.” Dijkstra's tentative labels can also improve repeatedly. Its distinguishing property is that nonnegative weights justify permanently finalizing a minimum label.

The Princeton Dijkstra implementation contract explicitly requires nonnegative weights. A simple dense implementation uses $O(|V|^2)$ time. A binary-heap implementation with stale-entry skipping can use $O((|V|+|E|)\log |V|)$ on the usual finite graph model. These bounds describe the algorithm and data representation, not actual travel-data acquisition costs.

4. A tour requires one connected cycle 06:21

The traveling salesperson problem, TSP, seeks a minimum-cost cycle that visits each city exactly once and returns to its start. Such a cycle is Hamiltonian. With $n$ labeled cities and one fixed starting city, there are $(n-1)!$ directed orderings. If costs are symmetric and reverse tours are identified, there are $(n-1)!/2$ distinct orientations for $n\ge3$. Fixing the starting point removes rotational duplicates; it does not change the cycle's total cost.

Let $c_{ij}$ be the cost of traveling from city $i$ to city $j$, and let the binary decision variable $x_{ij}$ equal one when the chosen tour uses that arc. The costs describe what is available. The variables describe what is chosen. For unavailable arcs, omit the variable or force it to zero; do not define $x_{ij}$ as mere reachability.

The objective is $\min\sum_{i\ne j}c_{ij}x_{ij}$. Each city must have one departure and one arrival:

$$\sum_{j\ne i}x_{ij}=1,\qquad \sum_{i\ne j}x_{ij}=1,\qquad x_{ij}\in\{0,1\}.$$

These are assignment constraints. They create a disjoint collection of directed cycles covering all vertices, called a cycle cover. They do not require one cycle containing every city. An assignment solver therefore gives a relaxation and lower bound for TSP, rather than a general exact TSP solution.

In our four-city construction, cities 1 and 2 form one cheap pair, and cities 3 and 4 the other. The assignment $1\to2\to1$ and $3\to4\to3$ costs $1+1+1+1=4$. It satisfies every arrival and departure equation. It is not a four-city tour. A legal tour must cross between the pairs at least twice. Its cheapest possible cost is $9+9+1+1=20$, attained by $1\to2\to3\to4\to1$.

To exclude subtours, add for every nonempty proper subset $S\subset V$ the constraint

$$\sum_{i\in S}\sum_{j\notin S}x_{ij}\ge1.$$

Every proper subset must have an outgoing selected arc. A disjoint cycle would violate this inequality for its own vertex set. Conversely, a cycle cover with no proper closed subset must consist of one cycle. This establishes why the additional constraints impose the missing connectivity.

There are exponentially many subset constraints. An exact solver can generate them as needed: solve a relaxation, identify an offending subtour, add a violated constraint, and repeat within an integer-programming search. A row/column reduction is useful for a lower bound but does not replace connectivity reasoning. Forcing one small positive reduced-cost entry and accepting the first resulting tour is not a general proof of global optimality; every remaining alternative needs a valid bound or exhaustive exclusion.

If an optimal assignment already consists of one Hamiltonian cycle, its cost is simultaneously a TSP lower bound and a feasible TSP upper bound, so it is optimal. This is a valid special-case certificate. Otherwise the gap between cycle-cover cost and tour cost can be large, as the 4-versus-20 construction shows.

5. What computational hardness does and does not say 01:24

For integer-encoded costs, the decision question “is there a tour costing at most $K$?” has a short certificate: a proposed city ordering can be checked in polynomial time. This decision version is NP-complete. The optimization problem is NP-hard. The class NP concerns polynomial-time verifiability, or equivalently a nondeterministic computation model; it does not mean “known to require nonpolynomial time.”

No general polynomial-time exact algorithm for TSP is known. Proving that none exists would resolve the P-versus-NP question. Hardness also does not forbid exact solutions of finite instances, special-case algorithms, or practical branch-and-bound performance. The lab enumerates a tiny instance exactly. Its exponential growth is a limitation of exhaustive enumeration, not a proof that every possible algorithm must enumerate every tour.

One reduction explains the basic difficulty without relying on terminology. Given an undirected graph with $n$ vertices, construct a complete graph with cost 1 for existing edges and cost 2 for missing edges. Every Hamiltonian tour has $n$ arcs. It has cost at most $n$ exactly when all its arcs correspond to edges of the original graph, so it reveals an original Hamiltonian cycle. A polynomial exact TSP solver would therefore solve the Hamiltonian-cycle decision problem through this polynomial construction.

For a delivery application, a useful workflow distinguishes a valid tour, an objective lower bound, and a provable approximation ratio. A heuristic can return a legal route quickly while lacking either optimality proof or worst-case ratio. Reporting “near optimal” merely because it looks short supplies neither kind of evidence.

6. A metric assumption permits a bounded approximation 49:20

A metric TSP uses a complete undirected graph with nonnegative symmetric costs satisfying the triangle inequality $c_{ij}\le c_{ik}+c_{kj}$. These hypotheses are substantive. Direct road distance, monetary fare, or setup cost need not satisfy them. Shortest-path distances in a connected undirected nonnegative road network do form a metric, with a pseudometric if distinct vertices can have zero distance.

A spanning tree connects every city without cycles. A minimum spanning tree, MST, minimizes the sum of its edge costs. Its cost is a lower bound on a minimum tour: deleting any edge of an optimal tour leaves a spanning path, hence a spanning tree, and nonnegative costs cannot increase upon deletion.

Double every MST edge. The resulting multigraph has even degree at every vertex and admits a closed walk that traverses each doubled edge exactly once. Equivalently, a depth-first traversal of the tree goes down and back along every tree edge. Its cost is exactly twice the MST cost. This walk repeats cities, so it is not yet a TSP tour.

Keep each city only on its first visit and shortcut the repeated portions, finally returning to the root. The triangle inequality ensures that replacing a multi-edge segment by its direct connection cannot increase cost. The result is a Hamiltonian cycle of cost $C_{\mathrm{alg}}$ satisfying

$$C_{\mathrm{opt}}\le C_{\mathrm{alg}} \le2C_{\mathrm{MST}}\le2C_{\mathrm{opt}}.$$

This is a factor-two approximation guarantee under the metric assumptions. It does not say the returned tour is optimal or that it lies close to optimum in every instance. The proof identifies exactly where each hypothesis is used: nonnegativity supports the tree lower bound, symmetry supports doubling undirected edges, completeness makes shortcuts available, and the triangle inequality bounds shortcut costs. For the general definition of an approximation ratio, see MIT 6.046J, lecture 17, page 1. The metric-tour bound itself is proved above.

For a counterexample without the triangle inequality, a cheap tree traversal can be shortcut by a very expensive direct arc. Removing repeated vertices is then a combinatorial operation that increases cost. Using an MST procedure on arbitrary directed fares also lacks the undirected proof. The correct response is to change the model or algorithm, not silently keep the guarantee.

7. Executable comparison and operational limits

The chapter laboratory implements Dijkstra with a heap, exact enumeration for tiny TSP instances, and an MST-preorder tour on five Euclidean points. The Dijkstra routine accepts a finite adjacency dictionary with known vertices and finite nonnegative weights. It returns distances and one predecessor relation, rejects negative weights, and leaves unreachable vertices at infinity. Its heap tie handling assumes mutually comparable vertex labels, as in the supplied string-labeled example.

The lab checks shortest cost 4, assignment bound 4, and exact four-city tour cost 20. On points $(0,0),(2,0),(2,1),(0,1),(1,3)$ it obtains MST cost $6.236067977$, preorder-tour cost $8.472135955$, and exact tour cost $8.472135955$. The equality of the latter two is a fact about this small construction. The meaningful general check is the proved inequality, not an expectation that every preorder tour is exact.

Enumeration fixes the starting vertex and considers each ordering of the remaining vertices. It is independently structured from Prim's MST construction and the preorder traversal. The assertions check that every city is visited once, the tour closes, and the approximation respects both the tree bound and exact optimum on this instance. No files, network resources, or actual route services are changed.

The formal graph can hide real operational constraints. A shortest route ignoring departure time may become slower under congestion. A tour ignoring vehicle capacity may be physically impossible. A shortest-path distance between two required customers may pass through another required customer; distinguishing transit visits from service visits is then necessary when interpreting the metric closure. Define those semantics before treating a graph certificate as a deployable route plan.

Exercises

  1. Trace all tentative labels and predecessors for the five-arc shortest-path construction. Explain when the destination label becomes final.
  2. Give a negative-edge graph with no cycle where a label-setting Dijkstra implementation fails. Locate the exact failed proof inequality.
  3. Construct a source shortest-path tree that does not give the shortest path between two non-source vertices.
  4. Prove the assignment lower bound of 4 and TSP optimum of 20 for the two-cheap-pairs construction.
  5. Prove that subset outgoing-arc constraints eliminate every proper subtour in an integer cycle cover. Why is the word “integer” consequential?
  6. Derive the metric doubled-tree bound and identify what must be rechecked when road costs are asymmetric or do not satisfy the triangle inequality.
Fully worked solutions

  1. Initialize $d(s)=0$ and the other labels at infinity. Settle $s$: $d(a)=4,\pi(a)=s$ and $d(b)=1,\pi(b)=s$. Settle $b$: $d(a)=3,\pi(a)=b$ and $d(t)=8,\pi(t)=b$. Settle $a$: $d(t)=4,\pi(t)=a$. Selecting $t$ as the minimum unsettled vertex makes its label final by the nonnegative-edge invariant. The discovered label 8 was not final merely because a route to $t$ existed.

  2. Use $s\to a$ of cost 2, $s\to b$ of cost 5, and $b\to a$ of cost $-4$. The graph is acyclic. Dijkstra finalizes $a$ at 2 before discovering the route costing $5-4=1$. On that route, the prefix to $b$ costs 5, greater than the full cost 1. The proof step $\delta(s,y)\le\delta(s,u)$ fails when the remaining segment can be negative.

  3. In an undirected graph let edges $s-a$ and $s-b$ have cost 1 and edge $a-b$ cost $1/2$. The shortest-path tree rooted at $s$ uses both unit edges because each is the cheapest source route. Its path from $a$ to $b$ through $s$ costs 2, while the direct graph edge costs $1/2$. A source tree preserves distances from its root, not arbitrary pairwise distances.

  4. Each selected assignment arc has cost at least 1 and there are four arcs, so cost is at least 4. Two separate two-cycles attain it. A Hamiltonian cycle must leave the first pair and later return to it, using at least two cross-pair arcs of cost 9. The remaining two arcs cost at least 1 each, giving lower bound 20. The cycle $1,2,3,4,1$ attains 20, so the bound is exact.

  5. Arrival/departure equalities and binary variables give every vertex indegree and outdegree one in the selected graph, hence a union of disjoint cycles. If more than one cycle exists, choose the vertex set $S$ of one cycle. It has no outgoing selected arc and violates the constraint. If exactly one cycle exists, every nonempty proper subset has an outgoing arc along that cycle. Fractional variables do not define a literal cycle cover: the constraints describe a relaxation whose feasible points can distribute flow among arcs. Additional integrality is needed before this combinatorial proof identifies one tour.

  6. Removing an arc from an optimal tour yields a spanning tree of no greater cost. Therefore $C_{\mathrm{MST}}\le C_{\mathrm{opt}}$. Doubling the MST gives a closed walk of cost $2C_{\mathrm{MST}}$. Metric shortcuts cannot increase cost, so the resulting tour is at most this amount and hence at most twice optimum. For asymmetric costs, a reverse tree arc can have another cost or be unavailable, invalidating the doubled-undirected-tree construction. Without the triangle inequality, shortcutting can increase cost. Either change the distance representation with a justified closure or use an algorithm with assumptions appropriate to the new problem.

"""Shortest paths, subtours, and a metric TSP approximation."""
from heapq import heappop, heappush
from itertools import permutations
from math import hypot, inf, isclose, isfinite


def dijkstra(graph, source):
    """Nonnegative finite weights; return distances and one predecessor tree."""
    if source not in graph:
        raise ValueError("source is absent")
    if any(v not in graph or not isfinite(w) or w < 0
           for neighbors in graph.values() for v, w in neighbors):
        raise ValueError("known vertices and finite nonnegative weights required")
    distances = dict.fromkeys(graph, inf)
    previous = dict.fromkeys(graph)
    distances[source] = 0
    queue = [(0, source)]
    while queue:
        distance, u = heappop(queue)
        if distance != distances[u]:
            continue
        for v, weight in graph[u]:
            candidate = distance + weight
            if candidate < distances[v]:
                distances[v] = candidate
                previous[v] = u
                heappush(queue, (candidate, v))
    return distances, previous


def brute_tour(cost):
    """Fix start at 0 and enumerate tours; intended only for tiny instances."""
    n = len(cost)
    return min((sum(cost[u][v] for u, v in zip(route, route[1:])), route)
               for tail in permutations(range(1, n))
               for route in [(0,) + tail + (0,)])


def tree_tour(points):
    """Prim MST plus preorder shortcut tour for a complete Euclidean graph."""
    n = len(points)
    cost = [[hypot(a[0] - b[0], a[1] - b[1]) for b in points] for a in points]
    tree = [[] for _ in points]
    reached = {0}
    tree_cost = 0
    while len(reached) < n:
        weight, u, v = min((cost[u][v], u, v) for u in reached
                           for v in range(n) if v not in reached)
        tree[u].append(v)
        tree[v].append(u)
        tree_cost += weight
        reached.add(v)
    order = []

    def visit(u, parent):
        order.append(u)
        for v in sorted(tree[u]):
            if v != parent:
                visit(v, u)

    visit(0, None)
    route = order + [0]
    length = sum(cost[u][v] for u, v in zip(route, route[1:]))
    return tree_cost, length, route, cost


if __name__ == "__main__":
    graph = {"s": [("a", 4), ("b", 1)], "b": [("a", 2), ("t", 7)],
             "a": [("t", 1)], "t": [], "z": []}
    distances, previous = dijkstra(graph, "s")
    assert distances == {"s": 0, "b": 1, "a": 3, "t": 4, "z": inf}
    assert previous["t"] == "a" and previous["a"] == "b"
    try:
        dijkstra({0: [(1, -1)], 1: []}, 0)
        raise AssertionError("negative edge was accepted")
    except ValueError:
        pass
    cost = [[inf, 1, 9, 9], [1, inf, 9, 9],
            [9, 9, inf, 1], [9, 9, 1, inf]]
    assignment = min(sum(cost[i][p[i]] for i in range(4))
                     for p in permutations(range(4)))
    optimum, route = brute_tour(cost)
    assert assignment == 4 and optimum == 20
    mst, approximate, order, matrix = tree_tour(
        [(0, 0), (2, 0), (2, 1), (0, 1), (1, 3)])
    exact, exact_order = brute_tour(matrix)
    assert mst <= exact + 1e-12
    assert exact <= approximate + 1e-12
    assert approximate <= 2 * mst + 1e-12
    assert len(set(order[:-1])) == 5 and order[0] == order[-1]
    print("shortest=4; assignment=4; TSP=20")
    print("metric MST=%.9f; preorder=%.9f; optimum=%.9f" %
          (mst, approximate, exact))
