A deployment can have every individual task finish within its estimate and still miss its launch date. The estimates may have ignored a dependency, assumed the same engineer could work on two tasks simultaneously, or assigned too little protection to several paths that merge. Scheduling begins by distinguishing these failures. A precedence model answers when work could finish with sufficient resources. A resource-constrained schedule and a probability model answer additional questions.

Consider an original teaching project with seven activities. A duration is measured in days. The project starts at event 1 and finishes at event 6. Activity names identify work; event numbers identify milestones with no duration of their own.

Activity Tail event Head event Duration
A 1 2 3
B 1 3 2
C 2 4 4
D 3 4 6
E 2 5 2
F 4 6 2
G 5 6 4

Activities A and B may start together. C and E need A. F needs both C and D. The final milestone requires both F and G. These are logical requirements, not recommendations to use particular people or machines. We will derive the minimum completion time, identify permissible delays, add uncertainty, and then ask what paying for faster work actually buys.

1. A network is a set of precedence claims 10:21

A project is a temporary collection of activities directed toward a defined outcome. A work breakdown structure decomposes the outcome into manageable work packages. It answers what work exists. A precedence network adds the relations that determine which activities must finish before other activities can begin. A decomposition alone does not determine a schedule.

Formally, a directed graph is a pair $(V,E)$, where $V$ is a finite set of vertices and $E$ is a set of ordered pairs of vertices called arcs. In an activity-on-arrow representation, an arc $(i,j)$ is an activity and its endpoints are events. Its nonnegative duration is $t_{ij}$. In an activity-on-node representation, vertices are activities and arcs express precedence. Both conventions can represent deterministic critical-path analysis or uncertain-duration PERT analysis. Representation is not a mathematical distinction between the two methods.

A directed path follows arcs in their prescribed directions. A directed cycle would require a chain of work to finish before it can begin. Ordinary finish-to-start project models therefore use a directed acyclic graph, or DAG. An iteration such as repeated testing must be resolved into a finite plan or represented by a richer stochastic model; drawing a positive-duration cycle does not make the ordinary critical-path recurrence applicable.

Our numbering is topological: every arc has $i<j$. This is a convenient ordering of events, not a statement that all lower-numbered events occur earlier in clock time. Events 2 and 3 can be reached independently. A topological order exists for every finite DAG. One construction repeatedly removes an event with no incoming arc from the remaining graph. If no such event exists while vertices remain, following predecessors must eventually revisit a vertex, exposing a cycle.

Dummies preserve logic rather than perform work 24:37

An activity-on-arrow diagram sometimes needs a dummy activity, an arc with zero duration and no resource consumption. Suppose activities A and B must both finish before D, while E needs B alone. Merging the endpoints of A and B would accidentally make E depend on A. Keeping their endpoints distinct and adding a zero-duration arc from B's completion to the event starting D preserves the intended dependency.

A dummy is justified by the precedence relation it encodes. Adding arbitrary zero-duration arcs can introduce dependencies that the project never required. Removing a dummy because it has no cost can erase a real constraint. Conversely, a redundant arc whose relation is already implied by a directed path adds no timing restriction. The correct test is logical equivalence, not visual tidiness.

Multiple starting or finishing activities can be connected to a super-source or super-sink with zero-duration arcs. This makes project completion mean that every required terminal activity has finished. A disconnected branch is not harmless merely because it is absent from the drawn critical path: it may be omitted work. Check that every activity lies on a source-to-sink path before calculating dates.

The network also contains assumptions that a drawing cannot validate. Durations are fixed for the deterministic calculation. Tasks can begin as soon as their predecessors finish. Resources are sufficiently available to realize all such starts. Calendars, setup times, and resource conflicts require explicit constraints. A ten-day critical path is a lower bound for a project that must serialize two otherwise parallel tasks on one unavailable machine.

2. Forward and backward passes solve different inequalities 08:05

Let $E_i$ denote the earliest possible occurrence time of event $i$, measured from a project start at zero. Every incoming activity imposes the inequality $E_j\ge E_i+t_{ij}$. Event $j$ requires all its predecessors, so satisfying only the shortest incoming branch is insufficient. The earliest time satisfying every incoming inequality is

$$E_1=0,\qquad E_j=\max_{(i,j)\in E}(E_i+t_{ij}).$$

Evaluate this recurrence in topological order. The calculation is exact for the stated deterministic precedence model. Its proof is an induction: every incoming path reaches $j$ no earlier than its own duration, while scheduling all preceding activities at their earliest starts realizes the maximum when resources impose no additional restriction.

For our project, $E_2=3$ and $E_3=2$. At the merge, $E_4=\max(3+4,2+6)=8$. The shorter branch must wait for the longer one. Next $E_5=3+2=5$, and $E_6=\max(8+2,5+4)=10$. Ten days is the minimum project duration in this model.

The three source-to-sink path durations provide an independent check: A–C–F takes 9, B–D–F takes 10, and A–E–G takes 9. Project completion is governed by the longest path because all required work must finish. This longest-path problem is tractable on a DAG; the recurrence visits each activity once after ordering the graph. It is different from longest simple paths on arbitrary directed graphs.

Let $L_i$ denote the latest occurrence time of event $i$ compatible with the chosen completion deadline $T$. For the minimum-duration schedule set $T=E_6=10$. If activity $(i,j)$ is to finish by $L_j$, its tail must occur by $L_j-t_{ij}$. Every outgoing activity must remain possible, so the backward recurrence is

$$L_6=T,\qquad L_i=\min_{(i,j)\in E}(L_j-t_{ij}).$$

Evaluate in reverse topological order. A minimum appears because the tightest successor controls how late an event may occur. Confusing this minimum with the forward maximum creates schedules that violate at least one successor's deadline.

For the running project, $L_4=8$ and $L_5=6$. Then $L_2=\min(8-4,6-2)=4$, $L_3=8-6=2$, and $L_1=\min(4-3,2-2)=0$. The two passes give the following complete event table.

Event Earliest time $E_i$ Latest time $L_i$ Event slack $L_i-E_i$
1 0 0 0
2 3 4 1
3 2 2 0
4 8 8 0
5 5 6 1
6 10 10 0

The backward pass can instead use an externally imposed deadline. A deadline of 9 gives negative slack somewhere because the original durations require at least 10. Negative slack reports an inconsistent deadline under the current model; it does not make an activity physically shorter. Some activity durations or requirements must change before that deadline is feasible.

3. Floats measure particular kinds of scheduling freedom 24:02

For an activity $(i,j)$, its earliest start and finish are $ES_{ij}=E_i$ and $EF_{ij}=E_i+t_{ij}$. Its latest finish and start are $LF_{ij}=L_j$ and $LS_{ij}=L_j-t_{ij}$. The total float is

$$TF_{ij}=LS_{ij}-ES_{ij}=L_j-E_i-t_{ij}.$$

This is the maximum delay available to that activity relative to its earliest start while retaining the selected final deadline and allowing other work to be rescheduled. The word “total” matters: several activities can draw on the same flexibility. Total floats are not independent savings accounts that can all be spent simultaneously.

An activity is critical for the minimum-duration schedule when its total float is zero. In the running project, B, D, and F have zero total float; A, C, E, and G each have one day. The critical path B–D–F has duration 10. Increasing any activity on this path by a small positive amount increases project duration by that amount while it remains controlling.

Zero event slack at both endpoints is insufficient to establish a critical activity. There can be a shorter arc between two events that are fixed by other longer paths. The activity itself must fill the difference between the event times. The total-float equation checks this condition directly rather than inferring it from endpoint labels.

The free float is

$$FF_{ij}=E_j-E_i-t_{ij}.$$

It measures the delay that leaves the head event at its earliest time. Activity A has total float 1 but free float 0: delaying A immediately delays event 2 and therefore changes the earliest starts of C and E. Activity C has free float 1 because D already keeps event 4 waiting until day 8. Hence $0\le FF_{ij}\le TF_{ij}$ when the backward deadline is the minimum project duration.

The independent float, under the conventional nonnegative reporting rule, is

$$IF_{ij}=\max(0,E_j-L_i-t_{ij}).$$

It asks what freedom remains if the tail event occurs as late as permitted while the head event must retain its earliest time. A negative raw expression means there is no such guaranteed freedom; reporting zero does not assert those endpoint choices are jointly compatible without rescheduling. The interfering float is $TF_{ij}-FF_{ij}$. Spending it can affect successor timing even while final completion remains protected.

Critical paths need not be unique. Increase E's duration from 2 to 3. A–E–G now also takes 10. Finishing B earlier cannot make the project finish before the competing path. A project manager must monitor every binding branch, including near-critical paths that can become binding after a small perturbation.

The distinction generalizes to the value of an intervention. A task can be operationally important despite positive float if it has uncertain duration, scarce specialist resources, or safety consequences. Critical-path analysis ranks timing constraints in one deterministic model; it is not a complete ranking of managerial attention.

4. PERT models activity uncertainty, then approximates a path 02:39

The Program Evaluation and Review Technique, PERT, uses three duration estimates for each activity: an optimistic value $a$, a most likely value $m$, and a pessimistic value $b$, with $a\le m\le b$. The conventional moment estimates are

$$\mu=\frac{a+4m+b}{6},\qquad \sigma^2=\left(\frac{b-a}{6}\right)^2.$$

The mean gives four times as much weight to the most likely estimate as to either endpoint. The spread formula treats the estimated range as approximately six standard deviations. These are modeling formulas, not identities determined by three arbitrary observations. A beta family can motivate a bounded, asymmetric duration model, but endpoints and a mode alone do not uniquely imply both formulas for every beta distribution.

A mean is also not generally a median. For an asymmetric duration distribution, completing by the mean need not have probability one half. The normal approximation later used for a path has equal mean and median, which can hide this distinction. Calling an activity's estimated mean its “50% completion time” imports a distributional claim that the mean formula does not establish.

For a fixed path $P$, let $X_e$ be random activity durations and $S_P=\sum_{e\in P}X_e$ its duration. Linearity of expectation gives $\mathbb E[S_P]=\sum_e\mu_e$ without independence. The variance is

$$\operatorname{Var}(S_P)=\sum_e\sigma_e^2+2\sum_{e<f}\operatorname{Cov}(X_e,X_f).$$

Only under zero covariance, in particular under independence, does it reduce to the sum of activity variances. A shared supplier or the same unavailable specialist can create positive dependence. Omitting that dependence understates fixed-path uncertainty.

As a numerical construction, give B the estimates $(1,2,3)$, D the estimates $(4,6,8)$, and F the estimates $(1,2,3)$. Their PERT means remain 2, 6, and 2. Under independent durations the fixed-path variance is $1/9+4/9+1/9=2/3$ day squared. The standard deviation is $\sqrt{2/3}$ days.

If we additionally approximate this fixed path by a normal random variable, its probability of finishing by day 11 is

$$\Pr(S_P\le11)\approx\Phi\!\left(\frac{11-10}{\sqrt{2/3}}\right)=0.889664319,$$

where $\Phi$ is the standard normal cumulative distribution function. A short path with one dominant uncertain activity has little reason to be close to normal. The central limit theorem is an asymptotic justification under assumptions, not a guarantee for every three-activity project.

A project is the maximum over paths 14:02

The random project completion time is $C=\max_P S_P$. In general, $\mathbb E[C]\ge\max_P\mathbb E[S_P]$: the maximum is at least each path duration pointwise, so its expectation is at least every path mean. Applying CPM to mean durations therefore produces a lower bound on expected completion, not an exact expected project time.

For a sharp finite counterexample, take two independent parallel path durations, each equal to 9 or 11 days with probability one half. Each path has mean 10. A calculation considering one path gives a one-half chance of finishing by 10. The project finishes by 10 only if both paths take 9, which occurs with probability one quarter. Its expected completion is $9(1/4)+11(3/4)=10.5$ days.

Real paths share activities and are consequently dependent even if individual activities are independent. A simulation can sample each activity once per trial, propagate the sampled durations through the whole network, and record final completion. Sampling each full path independently would erase shared-activity dependence. Simulation still depends on the chosen distributions and correlations; it cannot manufacture reliable optimistic and pessimistic estimates.

5. Crashing changes which paths bind 15:46

Crashing means paying additional direct cost to reduce an activity's duration. Let $t_e^N$ and $t_e^C$ be its normal and shortest permitted durations, and let $C_e^N$ and $C_e^C$ be corresponding direct costs. Under a linear interpolation model, the cost per day saved is

$$k_e=\frac{C_e^C-C_e^N}{t_e^N-t_e^C}.$$

This slope is defined only for a crashable activity with $t_e^N>t_e^C$. It need not be constant in an actual project. Overtime fatigue or discrete equipment rentals can produce nonlinear or discontinuous cost. An activity with identical normal and crash durations has no reduction to buy; dividing by zero is not a meaningful cost comparison.

In the original project, reducing B by one day makes B–D–F take 9. The other two paths also take 9, so the project now has three critical paths. Reducing B by another day alone leaves completion at 9. The second expenditure creates no further project-time benefit. A useful crashing algorithm must recompute critical paths after each change and compare coordinated reductions across all binding paths.

A continuous linear model avoids guessing combinations. Choose crash amounts $r_e\in[0,t_e^N-t_e^C]$ and event times $s_i$. For a target deadline $T$, minimize $\sum_e k_e r_e$ subject to $s_j\ge s_i+t_e^N-r_e$, $s_1=0$, and $s_6\le T$. This is an LP. Every path constraint is represented implicitly by its arc inequalities. If a common activity belongs to several critical paths, shortening it can benefit them together; otherwise several activities may need simultaneous reductions.

The economic optimum may differ from the shortest feasible project. Let $H(T)$ be indirect cost, such as site overhead, associated with finishing at time $T$. Compare the minimum direct cost achievable for each deadline with $H(T)$ and any explicitly modeled penalties. The shortest crash schedule can be more expensive in total than a slower schedule. A greedy smallest-slope rule requires care when paths change, shared activities interact, or costs are discrete.

6. Executable checks and the model's boundary

Run the chapter lab with python labs/ch06.py. Its input is a finite activity-on-arrow DAG whose integer labels are already topologically ordered. Durations must be finite and nonnegative. The routine returns earliest and latest event times and total floats; it raises ValueError for malformed ordering or disconnected milestones and does not modify files. It deliberately omits calendars and resource allocation.

The lab checks the event table against the forward/backward recurrence and independently enumerates every source-to-sink path. It verifies the unique critical path, a modified two-critical-path case, and the loss of benefit from shortening B after competing paths bind. It also evaluates the stated normal approximation and exactly enumerates the two-path uncertainty counterexample. The printed result is duration=10; critical=B,D,F; P(fixed path<=11)=0.889664319.

The Princeton Algorithms shortest-path materials provide a complementary algorithmic treatment of acyclic paths and precedence-constrained scheduling. The project recurrence here is derived explicitly rather than borrowing an algorithm guarantee without its DAG assumption. The source lectures supply the project-network, float, PERT, and crashing sequence; all seven-activity data and probability counterexamples above are original teaching constructions.

After this analysis, the project manager knows the earliest completion allowed by the stated dependencies, which deterministic delays it can absorb, and where uncertainty or extra resources could change that conclusion. The calculation does not establish that durations are accurate, workers are available, or the deliverable is safe and complete. Those require additional models and evidence.

Exercises

  1. Derive all earliest event times for the running network and prove that its minimum duration is 10.
  2. Calculate total and free float for A, C, and E. Explain why spending all their total floats independently is unsafe.
  3. Increase E's duration to 3. Identify every critical path and determine whether reducing D by one day shortens the project.
  4. For an activity with estimates $(a,m,b)=(2,5,14)$, calculate its PERT mean and variance. Does the mean identify the probability of completion by that time?
  5. Derive the exact completion distribution for two independent paths taking 9 or 11 days with equal probabilities. Compute its mean and the probability of meeting a ten-day deadline.
  6. Formulate the target-deadline crashing LP for the running network. Explain why it needs no explicit list of all paths and what changes if duration reductions must be integral.
Fully worked solutions

  1. From event 1 at time zero, A and B give $E_2=3$ and $E_3=2$. Event 4 waits for both C and D, so $E_4=\max(3+4,2+6)=8$. Event 5 occurs at $E_5=3+2=5$. Event 6 requires F and G, giving $E_6=\max(8+2,5+4)=10$. Any schedule needs at least the 10 days of B–D–F. Starting every activity at its earliest time meets all precedences and finishes at 10, establishing both a lower bound and an attaining schedule.

  2. For A, $TF=4-0-3=1$ and $FF=3-0-3=0$. For C, $TF=8-3-4=1$ and $FF=8-3-4=1$. For E, $TF=6-3-2=1$ and $FF=5-3-2=0$. Delaying A by one day already moves event 2 from 3 to 4. If C is independently delayed by another day relative to its new available start, it finishes at 9 and F finishes at 11. The nominal float calculations assumed a coordinated schedule, not independent additive permissions.

  3. A–E–G becomes $3+3+4=10$, tied with B–D–F. A–C–F remains 9. The two critical paths are therefore A–E–G and B–D–F. Reducing D by one day reduces only the latter path to 9. The former still takes 10, so project completion remains 10. Reducing an activity common to all binding paths would be effective, but these two paths share no real activity.

  4. The mean estimate is $(2+4(5)+14)/6=6$ days. The variance estimate is $((14-2)/6)^2=4$ day squared. These are moment estimates under the PERT convention. Without a specified distribution, they do not determine a cumulative probability. Even a distribution with exactly that mean and variance can put different probability mass below 6, so a one-half completion probability requires an additional symmetry or distributional argument.

  5. The four equally likely duration pairs are $(9,9),(9,11),(11,9),(11,11)$. Their maxima are 9, 11, 11, and 11. Hence $\Pr(C=9)=1/4$ and $\Pr(C=11)=3/4$. The mean is $9/4+33/4=10.5$. The ten-day success probability is $1/4$, even though either path individually meets that deadline with probability $1/2$. Taking the maximum before averaging is the consequential operation.

  6. For each arc $e=(i,j)$, choose $r_e$ and impose $s_j-s_i+r_e\ge t_e^N$. Add $0\le r_e\le t_e^N-t_e^C$, $s_1=0$, and $s_6\le T$. Minimize $\sum_e k_e r_e$. Summing arc inequalities along any path yields its duration bound, so all paths are enforced without enumeration. Conversely, feasible arc timings provide a feasible precedence schedule. Requiring integer $r_e$ changes the model to a mixed-integer linear program; rounding a continuous optimum may miss the target or overpay. Its cost is direct crash expenditure only unless overhead or penalties are added.

"""Critical-path analysis checked against independent path enumeration."""
from itertools import product
from math import erf, isclose, sqrt


EDGES = [
    (1, 2, 3, "A"), (1, 3, 2, "B"), (2, 4, 4, "C"),
    (3, 4, 6, "D"), (2, 5, 2, "E"), (4, 6, 2, "F"),
    (5, 6, 4, "G"),
]


def analyze(edges):
    """Return earliest/latest event times and activity total floats.

    Contract: integer nodes 1..n are topologically ordered; all durations
    finite and nonnegative; every node lies on a 1-to-n path.
    """
    from math import isfinite

    if not edges:
        raise ValueError("a nonempty DAG is required")
    nodes = sorted({v for u, v, _, _ in edges} | {u for u, _, _, _ in edges})
    if nodes != list(range(1, max(nodes) + 1)):
        raise ValueError("nodes must be 1..n")
    if any(u >= v or not isfinite(t) or t < 0 for u, v, t, _ in edges):
        raise ValueError("topological arcs and nonnegative durations required")
    earliest = {1: 0.0}
    for v in nodes[1:]:
        candidates = [earliest[u] + t for u, w, t, _ in edges if w == v
                      and u in earliest]
        if not candidates:
            raise ValueError("every node must be reachable from node 1")
        earliest[v] = max(candidates)
    latest = {nodes[-1]: earliest[nodes[-1]]}
    for u in reversed(nodes[:-1]):
        candidates = [latest[v] - t for w, v, t, _ in edges if w == u
                      and v in latest]
        if not candidates:
            raise ValueError("every node must reach the final node")
        latest[u] = min(candidates)
    floats = {name: latest[v] - earliest[u] - t for u, v, t, name in edges}
    return earliest, latest, floats


def paths(edges, node=1, labels=(), duration=0):
    """Enumerate all paths, independently of the forward/backward recurrence."""
    final = max(v for _, v, _, _ in edges)
    if node == final:
        return [(labels, duration)]
    result = []
    for u, v, t, name in edges:
        if u == node:
            result.extend(paths(edges, v, labels + (name,), duration + t))
    return result


if __name__ == "__main__":
    earliest, latest, floats = analyze(EDGES)
    assert earliest == {1: 0, 2: 3, 3: 2, 4: 8, 5: 5, 6: 10}
    assert latest == {6: 10, 5: 6, 4: 8, 3: 2, 2: 4, 1: 0}
    assert {k for k, v in floats.items() if isclose(v, 0)} == {"B", "D", "F"}
    assert max(t for _, t in paths(EDGES)) == earliest[6]
    tied = [(u, v, 3 if name == "E" else t, name) for u, v, t, name in EDGES]
    assert sum(t == 10 for _, t in paths(tied)) == 2
    assert analyze(tied)[0][6] == 10
    # Reduce B only: its former critical path becomes 9, so another path binds.
    crashed = [(u, v, t - (name == "B"), name) for u, v, t, name in EDGES]
    assert analyze(crashed)[0][6] == 9
    crashed_again = [(u, v, t - (name == "B"), name)
                     for u, v, t, name in crashed]
    assert analyze(crashed_again)[0][6] == 9
    variance = (2 / 6) ** 2 + (4 / 6) ** 2 + (2 / 6) ** 2
    probability = 0.5 * (1 + erf(1 / sqrt(2 * variance)))
    assert isclose(variance, 2 / 3)
    assert isclose(probability, 0.8896643190400766)
    # Two independent path times, each equally likely to be 9 or 11 days.
    outcomes = list(product((9, 11), repeat=2))
    assert sum(max(a, b) <= 10 for a, b in outcomes) / 4 == 0.25
    print("duration=10; critical=B,D,F; P(fixed path<=11)=%.9f" % probability)
